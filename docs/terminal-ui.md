# Terminal UI

`waivm-tui` is an optional terminal-native application for working with `waivm` programs.

It is not a React terminal interface, not a browser wrapper, and not a web dashboard. It is a standalone Rust CLI/TUI that talks to the existing `waivm` executable through the public command-line interface.

## Why this exists

The core VM already has serious systems value: C17 tooling, a NASM dispatch loop, bytecode files, a verifier, a debugger, and trace mode. The terminal UI adds a better human-facing workflow without contaminating the VM core with presentation logic.

The design goal is simple:

```text
systems core stays C/NASM
terminal experience lives in a separate Rust tool
all execution still goes through the real waivm CLI
```

## Build

Build the VM first:

```sh
cmake -S . -B build
cmake --build build
```

Build the TUI:

```sh
cargo build --manifest-path tui/Cargo.toml --release
```

Run it:

```sh
./tui/target/release/waivm-tui --root . --waivm ./build/waivm
```

Or set the VM path once:

```sh
WAIVM_BIN=./build/waivm ./tui/target/release/waivm-tui
```

## Optional CMake target

The TUI is not built by default because the core project should still build cleanly on a C/NASM-only system.

To request it through CMake:

```sh
cmake -S . -B build -DWAI_BUILD_TUI=ON
cmake --build build --target waivm_tui
```

## Controls

```text
Up/Down or k/j     select program
Left/Right or [/]  change action
Enter              execute selected action
r/t/v/d/i          run, trace, verify, disassemble, info
x                  temporarily leave TUI and open waivm debug
PageUp/PageDown    scroll output
c                  clear output
?                  toggle help
q or Esc           quit
```

## Commands exposed

The TUI exposes the existing CLI commands:

- `run`
- `trace`
- `verify`
- `dis`
- `info`
- `debug`

For `info` on a `.wai` source file, the TUI assembles the source into `.waivm-tui/<name>.waibc` first, then runs `waivm info` on the generated bytecode.

## Architecture

The TUI deliberately does not link against the C library and does not reimplement VM execution in Rust. That is intentional.

Benefits:

- the TUI dogfoods the public CLI
- the C/NASM execution path remains the source of truth
- the Rust layer stays replaceable
- debugger behavior remains consistent with `waivm debug`
- terminal UX can evolve without destabilizing the VM

## Implementation notes

The v6 TUI uses pure Rust standard library code plus ANSI escape sequences and `stty` for raw terminal mode. It has no external crate dependencies.

That keeps the tool lightweight and makes `cargo check` possible without downloading third-party packages.

## Limitations

- terminal UI targets Unix-like terminals
- it assumes `stty` exists
- it shells out to the `waivm` executable
- it does not provide inline source editing yet
- it does not embed the debugger inside a pane; pressing `x` temporarily exits the TUI and opens the existing interactive debugger
